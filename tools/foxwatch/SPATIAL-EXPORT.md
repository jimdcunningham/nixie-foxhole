# 3D Model Export

3D export starts once `prepare-refresh` and decoded mesh/material/texture preparation finish. It reads the fresh extraction manifest via `--catalog`, so rendered sprites and 2D publication are not prerequisites. The normal refresh runs CPU model export concurrently with GPU 2D rendering and waits for both before publication. Failure in either generation stage prevents publication; completed render and model caches remain available. Monitor Stop Run continues to stop the complete process tree.

Each persistent Node process exports one whole asset group, including its upgrade parts. Geometry simplification/compression and WebP texture encoding run in those processes; Blender builds the static GLBs with two CPU threads per process and does not render images on the GPU. Sharp uses one native compute thread per worker. The default ceiling is two CPU workers. `--spatial-workers 1..4` changes the requested ceiling; admission also reserves CPU capacity and 4 GiB of free RAM, budgeting 3 GiB per worker. One coordinator serializes model-index writes, so independent workers cannot replace each other's manifest entries.

Generated GLBs live at `types/<items|structures|vehicles>/<asset-id>/<model-id>.glb`. Base models and qualified upgrade parts share their owning asset directory with its textures and icons. `models/manifest.v1.json` remains the central index. Readers accept legacy `models/<model-id>.glb` entries while existing output transitions. The extension still packages all resources under `dist/assets/scene-v2/assets/<asset-id>/`.

The first new run can relocate verified legacy cached GLBs instead of re-exporting them. The compatibility snapshot is enabled only for the reviewed rendering implementation and validates the original input fingerprint plus every output hash, including when the generated asset checkout moved. A rendering-source change disables that compatibility automatically. New cache provenance excludes worker scheduling and progress code so orchestration changes do not invalidate geometry. Old model locations are removed only after the coordinator has written their new index entries. 2D cleanup preserves co-located GLBs.

Monitor shows a separate 3D progress bar with total/completed assets, exported/cached/skipped/failed counts, and each CPU worker's current model and phase. The 2D worker cards remain separate. Overall generation progress accounts for both stages; the old 2D-only remaining-time estimate is hidden while 3D work is unfinished.

Use `node tools/foxwatch/run-foxwatch.mjs export-3d --only <ids> --spatial-workers 2` for a targeted standalone export. `publish-manifest` publishes existing output and does not generate GLBs. Worker count, asset check/export/pack timings, and failures are written to `tools/foxwatch/tmp/spatial-timing-last.v1.json` after each run. Tests and benchmarks should use an isolated `--output-root`, `--temporary-root`, `--cache-root`, and `--timing-report`.

An isolated four-model packing benchmark on the local i7-8700K took 35.8 seconds with one worker and 21.9 seconds with two workers (1.64x), producing identical GLB hashes. This measures packing existing raw exports; it does not predict a full-refresh speedup or GPU-render overlap.
